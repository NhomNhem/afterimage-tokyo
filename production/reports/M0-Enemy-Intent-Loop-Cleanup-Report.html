1. Root Cause

Primary Issue: Scene Reference Desynchronization

The M0EnemyIntentLoopDriver component exists on Enemy_M0TargetablePlaceholder (GameObject instanceID 356648, component instanceID 356652) and is active in the scene hierarchy. The scene file (Gameplay_CombatPrototype.unity) contains the serialized reference loopDriver: {fileID: 500000013} in GameplayLifetimeScope.

However, at runtime during GameplayLifetimeScope.Configure() (called from LifetimeScope.Awake()), the serialized field loopDriver is null. This causes the strict validation to throw: 

InvalidOperationException: [M0Bootstrap] Required reference 'loopDriver' is not assigned in GameplayLifetimeScope.
Please assign M0EnemyIntentLoopDriver in the Inspector.

This is a Unity scene serialization/loading issue — the reference exists in the YAML scene file but Unity's deserializer is not resolving it into the C# field at runtime. This can happen after code changes, assembly reloads, or scene file modifications made outside the Unity Editor.

Secondary Issue: Previous Overpatches

The previous attempted fix introduced several anti-patterns that have been cleaned up:

  • FindObjectOfType<M0EnemyIntentLoopDriver>() fallback in GameplayLifetimeScope — removed
  • Reflection-based InjectLogger() method on M0EnemyIntentModel — removed
  • MonoBehaviour Update() as the source of enemy loop progression — replaced with explicit Tick(float)
  • Coroutine-based loop — removed
  • Duplicate RegisterComponent + RegisterInstance causing VContainer conflict — fixed
